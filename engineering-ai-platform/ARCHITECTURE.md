# Architecture

AxiomForge is a same-origin FastAPI service with a static browser client and Cloudflare Pages Functions for production routes. `backend/app.py` exposes health, deterministic PV/battery screening, simply supported beam screening, water and airflow screens, assistant routing and safe OpenAI conversational fallback. `frontend/app.js` owns the Three.js model, BIM metadata, view controls, module workspace registry, numerical SVG profiles and API/cloud calls. `frontend/index.html` is the page shell and grouped navigation; `frontend/styles.css` is the Quiet Industrial design system.

The model is versioned concept geometry, not a source-confirmed IFC. Components carry category, level, dimensions, material and provenance metadata. Blank BIM mode is deliberately separated from the opt-in Mbarara example. Solar and structural overlays are attached only after solver responses. Structural columns and the Mbarara building remain provisional and are not presented as construction-approved design.

Supabase stores authenticated projects, revisions, calculation records, file metadata and preferences. The migration `supabase/migrations/20261104000000_priority0_persistence_security.sql` adds composite child-to-parent ownership constraints, parent-aware RLS policies and the `save_calculation_atomic` RPC. The RPC verifies `auth.uid()`, locks by project, allocates the next integer revision and inserts revision plus calculation rows in one transaction. The browser stores local pending work separately and only displays `Saved to Cloud` after the required RPC returns successfully.

Cloudflare Pages Functions mirror the deterministic browser API contract. The frontend publishable key is the only Supabase credential in the browser; service-role credentials are not embedded. Anonymous RPC calls are rejected by the deployed Supabase API. Two-account authenticated isolation, signed private-file retrieval, account deletion, full scene-graph reconstruction, IFC/DXF/PDF parsing and isolated code execution remain incomplete capabilities.

The long-term architecture remains organized around domain packs: typed inputs, units, governing method, solver, validation benchmark, visualization, persistence and limitations. Advanced FEM, CFD, EPANET/SWMM, multiphysics, queues, notebooks and industrial integrations are future phases and are not implied by the current screening tools.
